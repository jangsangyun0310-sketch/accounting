# 본당살림

성당 사무실용 본당 회계·결산 관리 프로그램입니다. 여러 통장의 수입·지출과 잔액을 통합 관리하고 일일·월말·연말 결산서를 출력합니다.

- 화면: HTML / CSS / JavaScript (빌드 과정 없음)
- 서버: Cloudflare Workers. 구글 로그인, 성당·사용자 계정은 D1, **장부는 성당마다 따로 Durable Object(SQLite) 하나**
- 장부 규칙: `public/core` 엔진 (서버와 예전 브라우저 방식이 같은 코드)

## 시작하기

**https://bondang-salim.jangsangyun0310.workers.dev** 를 열고 **Google 계정으로 로그인**합니다.

1. 처음이면 성당 이름을 등록하고 정보 보관에 동의합니다.
2. 최초 설정(성당명, 통장과 초기잔액, 예산과목, 결재선)을 입력하면 바로 쓸 수 있습니다.
3. 홈 화면의 **[바탕화면에 아이콘 만들기]** 로 아이콘을 만들어 두면 다음부터 아이콘으로 엽니다.

- 장부는 본당살림 서버에 저장됩니다. 성당 PC·집 PC 어디서든 같은 구글 계정으로 로그인하면 같은 장부가 열립니다.
- 성당마다 저장소가 따로이고, 서버는 로그인한 사용자의 성당 저장소로만 요청을 보냅니다.
- 운영자는 문의 처리·자료 복구를 위해 장부 내용을 볼 수 있습니다 (가입할 때 동의).
- 설정 → 백업에서 장부 전체를 백업 파일(.json)로 내려받을 수 있습니다. 새 장부의 최초 설정 화면에서 그 파일로 복구합니다.
- 다른 성당에 알릴 때는 상단의 [🔗 공유하기] 로 사이트 주소만 보내면 됩니다.

### 예전 장부 파일(.bondang) 가져오기

2026-10-05 ~ 2026-10-08 에는 장부를 각 컴퓨터의 비밀번호 잠금 파일(.bondang)에 저장했습니다.
로그인 → 성당 등록 → 최초 설정 화면의 **[예전 장부 가져오기]** 에서 그 파일을 고르고 비밀번호를 넣으면 서버 장부로 옮겨집니다.

- 파일은 브라우저 안에서 비밀번호로 풀고(`public/js/local/`), 서버에는 풀린 자료만 보냅니다. 비밀번호는 서버로 가지 않습니다.
- 서버가 먼저 검사(손상·변조·마감 잔액)한 뒤 한 번에 전부 저장합니다. 고른 파일은 바뀌지 않습니다.
- 빈 장부에만 가져올 수 있습니다. 백업 파일(.json)도 같은 곳에서 가져옵니다.

## 폴더 구조

```
src/                 서버(Worker): 구글 로그인·세션·성당 등록, 화면 접근 제한(router.js), 성당별 장부 저장소(ledger.js)
  migrations/        서비스 계정 DB(D1) 표 구조
public/              프로그램 파일 (정적 파일)
  core/              회계 엔진: 거래·마감·결산 규칙 (/api/* 를 브라우저 안에서 처리)
  migrations/        장부(SQLite) 표 구조 (순서대로 적용)
  js/local/          장부 파일 열기·저장, 암호화, 브라우저 안 SQLite
  js/shared/         공용 모듈 (금액, 날짜)
  vendor/sqlite/     sqlite-wasm
seed/                테스트용 가상 데이터 (예시성당, 실제 성당 자료 아님)
test/                자동 테스트
```

## 개발 환경

Node.js 22.13 이상이 필요합니다.

```bash
npm install
npx wrangler d1 migrations apply bondang-salim-main --local   # 처음 한 번
npm run dev     # http://localhost:8787
npm test        # 금액 처리·장부 규칙·장부 파일 암호화·로그인 테스트
```

내 컴퓨터에서 구글 없이 시험하려면 `.dev.vars` 에 `DEV_LOGIN=1` 을 넣고
`http://localhost:8787/auth/dev-login?email=test@example.com` 으로 들어갑니다 (localhost 에서만 동작).

## 화면

| 주소 | 내용 |
|---|---|
| `/login` | 구글 로그인 (로그인 전에는 모든 화면이 이곳으로 이동) |
| `/signup` | 성당 등록: 처음 로그인한 사용자가 성당 이름 등록·정보 보관 동의 |
| `/setup` | 최초 설정 마법사 (설정 전에는 모든 화면이 이곳으로 이동). 예전 JSON 백업 파일로 복구도 여기서 |
| `/` | 홈: 통장별 잔액, 결재선 |
| `/entry` | 거래 입력: 수입·지출·이체 입력, 수정(취소 후 재입력), 취소, 하루 현황 |
| `/ledger` | 거래 조회: 기간·통장·과목·구분·검색어, 통장 선택 시 거래별 잔액 |
| `/closing` | 일 마감: 마감 달력, 마감·마감취소(메모 선택), 마감 시점 스냅샷 검증 |
| `/report` | 결산: 일일결산·월말결산·연말결산 A4 미리보기·인쇄 (마감 전은 "가결산" 표시) |
| `/settings` | 설정: 성당 정보, 통장, 예산과목, 결재선, 백업 사본 저장, 비밀번호 바꾸기 |

## 백업과 복구

- **백업:** 설정 → 백업 → [백업 사본 저장하기]. 지금 장부 파일의 사본(같은 비밀번호로 잠김)을 고른 곳에 저장합니다.
  USB·OneDrive 처럼 **그 컴퓨터 밖**에도 두세요. 홈 화면에 마지막 백업 일시가 나오고, 7일이 지나고 변경이 있으면 백업을 권합니다.
- **복구:** 시작 화면에서 [장부 파일 열기]로 백업 사본을 고르면 그대로 열립니다.
- **예전 JSON 백업 파일:** 새 장부의 최초 설정 화면 → "백업 파일로 복구하기".
  형식·검사값(SHA-256)·이체 쌍·예산과목 구분·마감 당시 잔액 재계산을 검사한 뒤, 한 번에 전부 저장하거나 전혀 저장하지 않습니다.

## 회계 데이터 원칙

- 금액은 원 단위 정수만 저장합니다 (DB `CHECK` 로 강제).
- 잔액은 저장하지 않습니다. `초기잔액 + 확정(POSTED) 거래 합계`로 계산합니다.
- 거래 삭제는 흔적 없이 지웁니다(화면에 남지 않음, 내부 기록만). 수정은 같은 번호로 내용만 바뀝니다. 마감된 날짜의 거래는 삭제·수정할 수 없습니다.
- 통장 간 이체는 출금·입금 두 거래가 한 쌍입니다. 한쪽을 지우면 DB 트리거가 반대쪽도 함께 지웁니다.
- 하루 현황은 `전일잔액 + 수입 − 지출 ± 이체 = 당일잔액` 을 통장·회계·전체 단위로 매번 검증합니다.
- 마감된 날짜(마지막 마감일 이하)의 거래는 DB 트리거가 변경을 막습니다.
- 마감은 날짜순으로만, 마감취소는 마지막 마감일부터 역순으로만 가능합니다.
- 마감·마감취소 이력과 감사 로그는 화면에 표시하지 않지만 내부에 자동으로 남고(추가만 가능), 백업 파일에도 포함됩니다.
- 마감 시 결재선과 통장별 잔액을 같은 SQL 문 안에서 스냅샷으로 저장합니다. 이후 조회 때 현재 계산 잔액과 비교해 불일치를 알립니다.
- 마감된 날짜가 있으면 새 통장은 초기잔액 0원으로만 만들 수 있고, 초기잔액이 있는 통장은 삭제할 수 없습니다.

## 배포 (개발자용)

```bash
npx wrangler login
npx wrangler d1 migrations apply bondang-salim-main --remote   # 표 구조가 바뀌었을 때
npm run deploy
```

구글 로그인 준비 (처음 한 번):

1. Google Cloud 콘솔 → API 및 서비스 → OAuth 동의 화면을 만들고, 사용자 인증 정보 → **OAuth 클라이언트 ID**(웹 애플리케이션)를 만듭니다.
2. 승인된 리디렉션 URI: `https://bondang-salim.jangsangyun0310.workers.dev/auth/google/callback` (내 컴퓨터 시험용은 `http://localhost:8787/auth/google/callback`)
3. 클라이언트 ID 는 `wrangler.jsonc` 의 `GOOGLE_CLIENT_ID` 에, 보안 비밀은 `npx wrangler secret put GOOGLE_CLIENT_SECRET` 으로 넣습니다.
